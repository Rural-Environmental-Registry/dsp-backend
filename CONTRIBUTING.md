# Contributing to rer-dsp-backend

Thank you for your interest in contributing to the DSP backend.

This repository is the REST API module of the **DSP (Data Sharing Platform)**,
part of the Rural Environmental Registry (RER). It exposes environmental and
geospatial data for sharing among partner institutions.

Please read the [Code of Conduct](CODE_OF_CONDUCT.md) before participating.

Full project documentation lives in
[dsp-docs](https://github.com/Rural-Environmental-Registry/dsp-docs).
The guide below covers this module only.

---

## What belongs here

Changes to the DSP REST API belong in this repository:

- Endpoints, services, and persistence (`br.car.dsp`)
- Tests under `src/test/java`
- Module configuration in `src/main/resources` and `application.properties`
- This module's `README.md`

Other DSP work belongs in its own repository:

| Change | Repository |
|--------|------------|
| Architecture, installation, and platform guides | [dsp-docs](https://github.com/Rural-Environmental-Registry/dsp-docs) |
| Web interface | [dsp-frontend](https://github.com/Rural-Environmental-Registry/dsp-frontend) |
| Stack orchestration, gateway, and adopter configuration | [dsp-core](https://github.com/Rural-Environmental-Registry/dsp-core) |
| Source-database migration | [dsp-job-data-migration](https://github.com/Rural-Environmental-Registry/dsp-job-data-migration) |
| Pre-generated download files | [dsp-job-geo-file-generation](https://github.com/Rural-Environmental-Registry/dsp-job-geo-file-generation) |

Labels, territorial hierarchy names, KPI cards, and map text come from
installation JSON generated by `dsp-core`. Do not hardcode adopter-specific
labels in Java.

## How to contribute

### 1. Bugs and features

1. Open an issue describing the problem or the change in the dsp-core repository:
   https://github.com/Rural-Environmental-Registry/dsp-core/issues
2. Fork the repository
3. Create a branch from `develop`: `git checkout -b feat/short-description`
4. Make the change
5. Run the tests: `./gradlew test`
6. Commit with a clear message
7. Open a pull request against `develop`

### 2. API changes

When you add or change an endpoint:

1. Declare the contract in `br.car.dsp.api`
2. Implement it in `br.car.dsp.controller`, keeping the controller thin
3. Put the behavior in `br.car.dsp.service`
4. Document the operation with springdoc (`@Tag`, `@Operation`)
5. Cover the change with a test in `src/test/java`

The API context path is `/dsp-backend`. Through the DSP gateway the same prefix
is used, with no rewrite.

### 3. Documentation of this module

Keep `README.md` limited to this module: purpose, stack, and how to run it.
Platform-wide guides (architecture, quick start, full installation) go to
[dsp-docs](https://github.com/Rural-Environmental-Registry/dsp-docs), in both
`docs/pt-br/` and `docs/en/`.

## Local setup

Requirements: Java 21 and the Gradle wrapper already in the repository
(`./gradlew`).

Run the API:

```bash
./gradlew bootRun
```

The preferred way to exercise the full stack (database, GeoServer, gateway, and
frontend) is `./start.sh` in
[dsp-core](https://github.com/Rural-Environmental-Registry/dsp-core).

Run the tests:

```bash
./gradlew test
```

The JaCoCo report is written to `build/reports/jacoco/test/html/index.html`.

## Code standards

- Java 21, Spring Boot 3.4.2, Gradle, JPA/Hibernate with PostGIS
- Source encoding is UTF-8
- Package root: `br.car.dsp`
- Request and response types live in `dto`; JPA entities live in `model`
- The operational database (`dsp-db`) serves business data. This API does not
  persist or return full geometries
- Schema management stays `none` (`SPRING_JPA_HIBERNATE_DDL_AUTO`). Do not
  generate the schema from the application
- Defaults for environment variables stay in
  `src/main/resources/application.properties`

## Review process

1. **Tests** — `./gradlew test` must pass
2. **Peer review** — at least one maintainer reviews the pull request
3. **Merge** — approved pull requests are merged into `develop`

---

## Commit message format

Use conventional commits:

```
feat: add territory boundary-box filter
fix: return empty attributes when detail fields are missing
test: cover WFS download fallback
docs: describe local bootRun in the module README
```

**Types:**

- `feat:` — new behavior
- `fix:` — bug fix
- `test:` — tests only
- `docs:` — documentation only
- `refactor:` — internal change with the same behavior
